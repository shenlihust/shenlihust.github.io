# 写作与维护

## 本地预览

使用 Ruby 3.4 与 Bundler：

```sh
bundle install
bundle exec jekyll serve --host 127.0.0.1
```

打开 http://127.0.0.1:4000 。修改 `_config.yml` 后需要重新启动预览。

macOS 如果默认 Ruby 版本过旧，可在当前终端执行：

```sh
export PATH="/opt/homebrew/opt/ruby@3.4/bin:$PATH"
```

## 发布文章

在 `_posts` 新建 `YYYY-MM-DD-english-slug.md`：

```yaml
---
title: "文章标题"
description: "一句话概括文章解决的问题"
date: 2026-10-20 10:00:00 +0800
categories: [原理与架构]
tags: [数据库, 索引]
toc: true
mermaid: true
---
```

正文使用 Markdown。分类建议使用 `原理与架构`、`源码解读`、`工程实践`、`实验记录`；标签按具体技术填写，例如 `Python`、`数据库`、`Kubernetes`、`Agent`。不限定技术领域，分类和标签页会根据已发布文章自动生成。`categories` 中的多个值表示层级，而非平行栏目。

草稿放到 `_drafts/slug.md`，使用 `bundle exec jekyll serve --drafts` 预览；默认构建不会发布草稿。文章图片建议放在 `assets/img/posts/文章标识/`。

## 构建与检查

```sh
JEKYLL_ENV=production bundle exec jekyll build
bundle exec htmlproofer _site --disable-external
```

## GitHub Pages

目标仓库：`shenlihust/shenlihust.github.io`。

创建仓库并上传本站源码后，在 Settings → Pages → Build and deployment 中选择 GitHub Actions。仓库已附带官方构建部署工作流，推送到 `main` 会自动构建和部署。

提交本地生成的 `Gemfile.lock` 前，执行 `bundle lock --add-platform x86_64-linux`，确保 Linux 构建环境可用。

## 修改样式

- 名称、简介、头像、主题模式：`_config.yml`。
- 关于页：`_tabs/about.md`。
- 侧边栏链接：`_data/contact.yml`。
- 更深入的样式调整：按 Chirpy 官方说明覆盖 `assets/css/jekyll-theme-chirpy.scss`，保留主题导入，再追加自定义样式。

优先保留主题默认模板，只覆盖确有需要的文件，减少后续升级成本。

参考：https://chirpy.cotes.page/posts/getting-started/
